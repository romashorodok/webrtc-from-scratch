# Full Peer Connection E2E Trace Coverage Matrix

## Scope and classification

This Stage 0 audit follows the packet path in
`performance_testing_tracing_full_peer_connection_e2e.md`, using the current
implementation only. **Covered** means the current performance-event baselines
exercise an explicit event at the boundary. **Partially covered** means an event
exists for an adjacent operation, an isolated test, or incomplete metadata, but
the full E2E baseline cannot assert the boundary. **Missing** means no applicable
performance event exists.

The audit includes the specified modules:

- `webrtc/ice/net/udp_mux.py`
- `webrtc/ice/agent.py`
- `webrtc/dtls/dtlstransport.py`
- `webrtc/srtp/session.py`
- `webrtc/transceiver.py`
- `webrtc/peer_connection.py`
- `webrtc/runtime.py`

## Baseline comparison

| --- | --- | --- |
| `tests/performance/baselines/pc_e2e_loopback_ice_dtls_srtp.json` | SDP/ICE lifecycle, STUN counters, DTLS record tx/rx, key derivation, and SRTP readiness. | No RTP or RTCP media crosses the selected transport. ## Contract and implementation notes for later stages

- Use the Stage 1 names above exactly where they overlap the approved event contract. The current isolated names `rtp.packetize.*` and `media.frame.verified` should be explicitly mapped or standardized before a full-E2E baseline asserts them.
- Attach existing correlation metadata where available: address/port and `size_bytes` for UDP; `pair_id` for ICE; DTLS record type/epoch/sequence; RTP/RTCP packet type, SSRC, sequence number, and encrypted/decrypted sizes.
- `CandidatePairController.start`, DTLS inbound receive, RTP receive, RTCP receive, and track receive are long-running ownership tasks. Record packet/phase events inside them; do not treat their task lifetime as a latency metric.
- The Stage 0 source audit found the public media-send surface incomplete. Stage 5 must resolve this on `PeerConnection` before the E2E test relies on public send helpers.
